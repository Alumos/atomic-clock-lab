# 任务二：原子钟揭秘

独立的原子钟与定位教学网页，与同级 `beidou-assembly-lab` 共用浅蓝灰、白色、深蓝文字与蓝色主按钮的视觉语言。参考 HTML 保存在 `reference/原子钟模拟器.html`，不参与网站部署。

## 本地预览

```bash
python3 -m http.server 18085 --bind 127.0.0.1 --directory site
```

打开 <http://127.0.0.1:18085/>。无需 npm 安装、账号、数据库或第三方 CDN。音效默认开启，在首次操作后由浏览器解锁；存在钟差时会持续发出间歇警报，钟差越大节奏越快；支持静音，切换到后台暂停。

## 教学活动

1. 在“单星偏差”和“四星不同偏差”之间切换；四星不同偏差模式可点击任一卫星，独立调节其钟差及快慢。
2. 依次体验十亿分之一秒、亿分之一秒、百万分之一秒、千分之一秒、十分之一秒和一整秒，观察测距误差和定位混乱程度。
3. 查看校园地图：绿色真实位置固定，橙色导航估计位置改变。每格 50 米，比例固定。
4. 用局部放大镜观察小误差；局部放大采用自适应比例，标注两点距离，不改变校园地图比例。偏差很大时，导航点会压缩到地图边缘，并通过画面抖动和警报音提示已经超出正常范围。
5. 切换“走快了 / 走慢了”，观察估计位置朝相反方向偏移。
6. 点击校准全部原子钟，观察两点重合；也可用自动演示完成偏移、暂停观察、校准流程。
7. 点击“原理说明”，查看教学模型、两种模式和预测题。说明采用弹窗，主界面保留地图与操作按钮。

主页面按屏幕高度分配空间，覆盖 1280×720、1366×768、1024×768、1920×1080 和 390×844 的一屏操作。极小屏幕保留最小可操作高度，可滚动；原理说明弹窗内部可滚动。

## 科学模型

时间偏差乘以光速得到**单颗卫星的测距误差**，不能直接当作最终定位偏差。本项目修正了参考 HTML 对二者的混用，不使用对数误差圈模拟真实地图距离，也不使用没有核实来源的原子钟寿命精度指标。

真空光速为 299792458 米/秒，1 纳秒对应 0.299792458 米测距误差。

模型使用固定四颗卫星方向，在局部二维平面线性化伪距方程，以最小二乘同时估计东西位置、南北位置和接收机钟差。每颗卫星的发射钟差范围为 0–1 秒，单星模式仅改变 1 号。快速档位分别为 1 纳秒、10 纳秒、1000 纳秒、1000000 纳秒、100000000 纳秒和 1000000000 纳秒。发射钟走快使该观测伪距偏短，走慢使伪距偏长；1 纳秒对应约 0.3 米，1 秒对应约 3 亿米测距误差。

四星不同偏差默认使用 [1000000, -700000, 400000, -900000] 纳秒，可分别调整；误差可能叠加，也可能部分抵消，不能简单相加。偏差越大，页面用急促提示音、画面抖动和红色警报边框强化“定位失控”的感觉。

地图比例只随视口尺寸适配，不随钟差变化。超出地图范围的估计位置会被压缩到边缘并标注“超出范围”；局部放大镜单独自适应。自动演示只在单星和四星不同偏差模式中运行，依次放大钟差、制造定位混乱，再统一校准。

大钟差下的位置结果是局部线性模型的外推，真实接收机可能无法解算。这是教学示例，不是实际北斗定位精度评估。不包含轨道、大气、多路径和真实系统校正；校准归零只清除本实验的钟差，不代表现实定位没有其他误差。地图卫星图标、传播速度为示意，不代替解算几何。

## 修改位置

| 文件 | 用途 |
| --- | --- |
| `site/index.html` | 标题、课堂引导、操作面板、科学说明 |
| `site/style.css` | 统一浅色配色、布局与响应式适配 |
| `site/model.js` | 四星平面定位模型，支持浏览器和 Node |
| `site/scene.js` | Canvas 校园地图、实际与估计标记、局部放大 |
| `site/app.js` | 滑杆、档位、走快走慢、校准、演示、音效与全屏 |
| `site/assets/satellite.svg` | 复用北斗项目的教学卫星插画 |

配色：页面 `#EEF4F8`，卡片 `#FFFFFF`，主文字 `#19364E`，辅助文字 `#526C80`，边框 `#C6D9E4`，主色 `#086F9A`，金色 `#A46514`，实际位置绿 `#168568`，估计位置橙 `#B4681D`。

使用原生 HTML/CSS/Canvas 2D，无 WebGL。避免 Canvas roundRect、可选链和动态视口单位；ResizeObserver、全屏、Web Audio 均有降级。支持 CSS Grid、Canvas 2D 的现代及较早期浏览器，未承诺 IE 或所有旧内核可用。尊重系统减少动态效果设置，仍可手动运行教学演示。

## Docker 部署

```bash
docker compose pull
docker compose up -d
```

默认端口 **18083**（北斗的部署端口是 18082），可修改 `compose.yaml`。健康检查 `/healthz`。网页是纯静态文件，也可直接把 `site/` 放入静态网站目录。页面保留同一备案链接，正式部署按实际域名备案信息修改。

源仓库：https://github.com/Alumos/atomic-clock-lab

推送 main 后，GitHub Actions 先验证源码、模型、容器和浏览器交互，再发布 `ghcr.io/alumos/atomic-clock-lab:latest`（linux/amd64）。本地源码构建使用 `docker compose -f compose.build.yaml up -d --build`。

## 验证

```bash
python3 scripts/check-assets.py
node --test scripts/model.test.cjs
```

浏览器检查需 Playwright 和 Chrome/Chromium：

```bash
node scripts/browser-smoke.cjs
```

可设置 `CLOCK_TEST_URL` 和 `CLOCK_CHROME_PATH`。检查包括单星倍数关系、六档时间跨度、四星独立编辑、快慢切换、全星校准、默认音效与静音、急促警报、混乱演示、手动打断、多尺寸一屏布局、手机、减少动态效果和旧 API 降级。截图在忽略提交的 `artifacts/` 内。
